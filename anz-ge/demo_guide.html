ANZ Institutional Banking Gemini Enterprise Dual-Agent Architecture

Automated Contract Governance & Compliance Demo

A complete presenter guide and data kit demonstrating how ANZ leverages Gemini Enterprise for both conversational contract vetting (Chat Agent) and zero-touch autonomous compliance routing (Workflow Agent) under strict APRA CPS 234 guidelines.

Section 1 Executive Overview & Dual-Agent Architecture

In Institutional Banking, reviewing hundreds of complex market data, trading software, and FinTech vendor contracts against APRA regulatory guidelines creates significant procurement bottlenecks. Gemini Enterprise provides two complementary paradigms to solve this:

Agent Type 1

Conversational Chat Agent

Role: Sourcing Specialist Co-Pilot

  • Invocation: Ad-hoc interactive chat window in Gemini Enterprise.
  • Ingestion: Upload draft contract PDF/DOCX/TXT directly into chat.
  • Knowledge: Embedded ANZ Market Data Procurement Guidelines (APRA CPS 234).
  • Output: Instant conversational verdict (Approved, Denied, Review Needed) with clause-by-clause legal rationale.
  • Best For: Interactive negotiation, clause queries, and on-the-fly redline checking.
Agent Type 2

Autonomous Workflow Agent

Role: End-to-End Enterprise Orchestrator

  • Invocation: Event-driven trigger on Google Drive folder drop.
  • Ingestion: Automatic file pickup from 01_Incoming_Contracts/.
  • Logic: Multi-branch decision engine evaluating 5 regulatory pillars.
  • Output: Generates formal audit artifacts directly to Google Drive folders:
    • 02_Approved_Contracts/ (Approval Memo)
    • 03_Rejected_Contracts/ (Rejection Notice)
    • 04_Pending_Human_Review/ (Escalation Brief + Review Task)
  • Best For: High-volume pipeline processing, compliance audit trails, and zero-touch operations.

System Execution Flow

📁 Google Drive Ingestion (01_Incoming_Contracts)
➔
⚡ Gemini Enterprise Workflow Engine

📜 Grounded Policy Evaluation (APRA CPS 234/230)
Branch 1: Clean Approval

Satisfies all 5 pillars (AU hosting, 99.99% SLA, 2x cap, NSW law). Generates Approval Memo to 02_Approved_Contracts.

Branch 2: Hard Rejection

Breaches hard triggers (US/EU hosting, no audit, 99.0% SLA). Generates Denial Notice to 03_Rejected_Contracts.

Branch 3: Human-in-the-Loop

Policy variances (Singapore DR, 99.95% SLA, 1x cap). Generates Escalation Brief to 04_Pending_Human_Review.

B. Single Prompt to Initiate Workflow Agent

Prompt: Workflow Agent Initialization
Create an automated contract compliance evaluation and routing workflow for ANZ Institutional Banking. Trigger: Monitor Google Drive folder "01_Incoming_Contracts" for newly uploaded contract files (PDF, DOCX, TXT). Processing Steps: 1. Extract contract text and metadata (Vendor Name, ACV, Effective Date). 2. Evaluate contract against ANZ Policy ANZ-POL-IB-PROC-2026-V3.2 across the 5 regulatory pillars (Data Sovereignty, APRA CPS 234 Audit, 99.99% SLA, 2x ACV Liability Cap, NSW Governing Law). 3. Branch on classification result: - Branch 1 (APPROVED): Generate "Contract Approval Memorandum", save to Google Drive folder "02_Approved_Contracts", and notify delegate. - Branch 2 (DENIED): Generate "Contract Rejection Notice" highlighting statutory breaches, save to "03_Rejected_Contracts", and alert sourcing team. - Branch 3 (REVIEW REQUIRED): Generate "Risk Escalation Brief", save to "04_Pending_Human_Review", and trigger a Human-in-the-Loop review task.

Manual Flow Wiring in Gemini Enterprise UI:

1. Trigger Node: Select Google Drive Connector ➔ Event: On New File Created ➔ Folder: /ANZ_Demo/01_Incoming_Contracts.

2. Agent Evaluation Node: Model: Gemini 1.5 Pro / Flash ➔ Knowledge Grounding: Select ANZ_IB_MarketData_Contract_Guidelines.md.

3. Conditional Switch Node:
• Condition A: verdict == 'APPROVED' ➔ Action: Create Doc in 02_Approved_Contracts.
• Condition B: verdict == 'DENIED' ➔ Action: Create Doc in 03_Rejected_Contracts.
• Condition C: verdict == 'REVIEW_REQUIRED' ➔ Action: Create Doc in 04_Pending_Human_Review + Create Human Review Task.

Section 7 Speaker FAQs & Objection Handling

Q: How does Gemini Enterprise avoid hallucinating compliance rules?

A: Gemini Enterprise uses strict grounding against ANZ's vectorized policy documents. It is instructed to extract exact clause references as citations. If a required term is absent from the contract, it treats it as a non-compliant deficiency rather than assuming or hallucinating terms.

Q: How does this satisfy APRA CPS 234 and CPS 230 audit trails?

A: Every evaluation executed by both the Chat Agent and Workflow Agent logs timestamped audit records, extracted parameters, model versioning, and the exact policy version evaluated against directly into Google Cloud Logging / BigQuery for regulatory inspection.

Q: Why have both Chat and Workflow agents instead of just one?

A: They solve different stages of procurement. Chat agents empower sourcing lawyers during active counterparty negotiations to test "what-if" compromises in seconds. Workflow agents handle batch governance, system-to-system automation, and regulatory triaging at scale with zero manual overhead.
